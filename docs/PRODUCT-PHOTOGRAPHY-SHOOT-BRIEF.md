# FN Workwear & Safety — Product Photography Shoot Brief

## Purpose

Create an accurate, consistent photo library for FN's real garments. The website currently contains third-party reference photographs and SVG illustrations; these are visual direction only, not evidence that the pictured items are FN-made products. Do not relabel, edit, or present a reference image as an FN product photograph.

## Before shooting

- Photograph only the actual garment/sample approved by FN.
- Assign each sample a product code, name, colour, fabric/composition (if confirmed), size/sample size, and revision.
- Record whether the image shows an actual FN sample, a buyer-approved sample, or a third-party inspiration reference.
- Steam garments, remove loose threads, close fastenings, arrange pockets and reflective tape consistently.
- Use the same camera position, neutral colour-managed lighting and background across the catalogue. A clean light neutral background is acceptable; do not force RGB-white if it changes reflective material or garment colour.
- Use a tripod and a normal-to-short-telephoto lens. A macro lens is useful for small construction details but is not essential for full-garment views.
- Photograph a colour reference/grey card at the start of each lighting setup. Match the garment to the physical sample; do not boost high-visibility colours artificially.

## Required capture set per garment

1. Front full-garment view.
2. Back full-garment view.
3. One side view; capture both sides only where construction differs.
4. Detail close-up 1: key construction (seam, reinforcement, pocket, closure, cuff or waistband).
5. Detail close-up 2: fabric, reflective tape, logo/label or other buyer-relevant feature.
6. Optional: inside lining, label, detachable components, or a second colour/variant where relevant.

For gloves and small accessories, include palm, back-of-hand, cuff and material/feature close-ups as relevant. For sets, photograph each component individually and together.

## File naming

Use lowercase, hyphenated names with a stable product code:

`<product-code>-<colour>-<view>.jpg`

Examples:
- `coverall-001-navy-front.jpg`
- `coverall-001-navy-back.jpg`
- `vest-004-hi-vis-orange-reflective-detail.jpg`

Never use a filename to claim a view that is not actually shown. Keep original camera files in an archive; export web-ready JPEG or WebP derivatives.

## Export and web delivery

- Preserve a high-resolution master. Export web images at up to 2048 px on the long edge (or larger if the source and use justify it).
- Create responsive derivatives only from the approved master: e.g. 1200 px and 600 px wide, plus a small thumbnail.
- Use modern WebP where supported and a JPEG fallback where required. Choose compression by visual inspection rather than forcing every file below a fixed KB limit.
- Keep a consistent crop and framing, but do not crop off garment features or distort aspect ratio.
- Provide descriptive alt text naming the garment, colour and actual view.
- Deliver a manifest mapping product code, view, filename, dimensions, format and approval status.

## Approval gate

Before any new photographs replace reference imagery on the public site, FN must confirm:
- the pictured garment is the correct FN sample/product;
- colour, construction, logos and features are accurate;
- all views are labelled correctly;
- no certification, protective performance or compliance claim is implied by the photograph alone.

## Current website limitation

The current repository's product pages do not contain the named JPG inventory in the supplied inspection report. That report's file paths and per-product dimensions were not verifiable against the repository. The current product showroom has 71 product cards and externally hosted reference images. New genuine multi-view galleries should be populated only after FN supplies and approves the matching image files. Missing angles must remain unavailable rather than being fabricated.

## Current web image delivery implementation (development branch)

- Product-card images are lazy-loaded below the fold and decoded asynchronously.
- Product images hosted on Shopify's image CDN receive responsive srcset candidates at 360, 640 and 960 pixels, with matching sizes values. The browser can select an appropriate derivative for the current layout.
- Shopify's image CDN negotiates modern image formats such as WebP/AVIF when supported by the requesting browser. This is CDN-side delivery, not a locally generated archive of WebP/AVIF files.
- Other third-party image hosts are intentionally not given fabricated resize or format parameters. Their URL conventions and format support differ; applying Shopify parameters to them could break images.
- The hero image retains high fetch priority. Product-card images remain lazy-loaded.
- The current product detail viewer displays the one supplied reference image for each card. It does not claim that browsing to another catalogue item reveals the back, side or construction detail of the same garment.
- A genuine multi-view gallery for a particular garment can only be assembled from independently verified images of that same garment/model. Where those views cannot be verified, the gallery remains a single-view reference rather than showing invented angles.

## Remaining verification limits

- Automated source-level smoke checks cover the responsive image enhancement and existing catalogue interactions.
- Manual desktop/mobile browser checks, visual colour review, and live network inspection still need to be completed in a real browser. Do not mark them complete based only on source inspection.
- Some external image providers may block hotlinking, change URLs, or serve different sizes over time. Recheck image availability and usage permissions before public launch.
